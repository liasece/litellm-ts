# 托管 CLIProxy 的调查与变更

本说明用于 CPA 运行、插件、升级和启动问题。它保存调查方法与兼容边界；运行版本、路径、超时、插件字段和接口能力从当前管理器、配置、构建与实际进程取得，不把本说明当作运行快照。

## 运行时和模型归属

网关启动镜像内的 `litellm-subscriptions`，并把已有账号卷投影给这个进程。版本随应用发布，旧版本目录和软链不参与启动。使用 `/subscriptions/status` 核实进程与版本。发布和回滚使用应用的标准部署入口。

模型部署分别保存公开别名、订阅 Provider 和原始上游模型 ID。账号来源由独立的 Provider 决定。检查图像、工具或流式响应时，核对原部署 ID、账单中的 Provider、私有请求路径及上游原始模型名。迁移与离线验证见[订阅运行时](../../native/subscriptions/README.md)。

## 插件和凭据

宿主从源码内置 CommandCode 与 OpenCode Go，插件目录接收运维安装的动态扩展，运行镜像使用 glibc。OAuth、轮询、额度、账号禁用、归档及恢复共享同一账号卷。配置自定义插件时核对目录、配置和实际加载结果。

CommandCode 插件源码由本仓库 `plugins/commandcode-go-cliproxyapi/` fork 维护，镜像从该目录编译，不直接用上游 release 替换。其 `FORK.md` 说明本地改动缘由，可在评估上游合并时参考；对照本地修复和调用方契约决定合并与验证，保留 Responses 工具兼容修复。账号配置、托管 auth 文件及额度能力从当前契约核实，不把某个套餐名称当作能力证明。插件额度是账号级窗口，不虚构按模型美元余额。

账号额度优先沿当前通用插件额度接口定位，provider 专用分支按代码中真实需要保留。账号管理与插件来源的背景可参考 [CommandCode 说明](../cliproxy-commandcode-goat-plugin.md)和 [OpenCode 说明](../cliproxy-opencode-go-plugin.md)。

## 升级与启动验证

运行时重启先排空在途请求。升级或回滚由应用镜像发布完成，现场核验宿主版本、实际进程和各订阅的真实请求。

应用监听不等待 CPA 就绪或远端模型价格拉取，预热在监听后异步进行；数据库迁移、遗留在途请求回收和路由装配仍在必要关键路径。启动问题可参考 [启动说明](../startup.md)，从当前装配与预热入口追踪，不把远端初始化加回服务装配关键路径。

验证同时检查当前版本、实际进程、插件加载、账号和模型调用行为；文件生成、配置保存、页面返回和真实请求成功分别判断。按实际风险覆盖排空、失败、恢复和密钥脱敏，生产动作按根入口的持续授权与部署 Skill 执行。
