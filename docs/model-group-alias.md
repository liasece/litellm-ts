# Model Group Alias 的每日时段路由

在 Dashboard 的 **Models & Endpoints → Model Group Alias** 中新增或编辑 Alias，设置默认目标，并按需添加每日时段。每个时段包含开始、结束和目标模型；时区默认填入 `Asia/Shanghai`，可以修改。

例如把 MiniMax 对应的模型组设为默认目标，再将 DeepSeek 对应的模型组设为谷价时段的目标。调用方始终使用同一个 Alias。供应商价格和谷价时间由管理员填写，程序不会查询或同步价格。

## 配置格式

保存在现有 `router_settings.model_group_alias` 中，不需要数据库迁移。旧字符串、数组和 `{ model, hidden }` 写法继续有效。数组仍取第一项作为路由目标。

下面的模型名和 22:00–06:00 仅用于说明跨午夜格式，并非供应商当前定价时间：

```yaml
router_settings:
  model_group_alias:
    cost-aware:
      model: minimax
      timezone: Asia/Shanghai
      schedule:
        - start: "22:00"
          end: "06:00"
          model: deepseek
```

`model` 是未命中任何时段时的默认目标；时段目标和默认目标都可以指向其他 Alias。删除全部时段后恢复全天使用默认目标。Dashboard 保存的是完整 Alias 映射，编辑一条记录会保留其他记录的附加字段。

## 时间与路由边界

- 每天按指定时区重复，以服务器时间为准，与服务器操作系统时区无关。页面的“Now”预览使用浏览器时钟。
- 时间采用 24 小时制 `HH:mm`。开始时间包含在内，结束时间不包含在内。结束早于开始时跨午夜；相同起止时间无效。
- 支持多个不重叠时段；相邻时段可以共用边界。非法时区、非法时间和重叠时段会在保存前被拒绝。
- 所有潜在的 Alias 路径都会校验循环，包括当前未生效的时段。默认目标不能指向 Alias 自己。
- 请求建立运行时配置快照时固定选择时间；同一个请求中的解析与重试保持一致，切换时刻之后的新请求使用新的时段目标。
- 已有 deployment 的 `override_model_name` 仍优先于同名 Alias。要让该源模型按 Alias 时段切换，需要清除与之冲突的固定覆写。
- 路由解析链仍记录所选目标。健康检查只检测当时选中的目标，不代表其他时段的目标可用；页面在目标变化后不再沿用旧目标的检查结果。
- 夏令时按当地实际墙上时间匹配：跳过的本地时间不会出现，重复出现的本地时间都按同一时段规则匹配。

该功能只决定路由目标，不修改供应商费用计算规则。
