3. 推理偏差：把脱敏占位符误判为"模板变量未展开"

模型的推理链显示出对占位符性质的错误理解，多轮排查偏离真实任务：

  • “the placeholder no longer expands (passes literal braces → hostname contains invalid characters)”
  • “the templating stopped substituting it. That's why ssh fails with hostname contains invalid characters.”
  • “quoting got mangled by the shell”——把脱敏标记误判为 shell 引号问题

这类偏差不表现为请求失败，但消耗多轮工具调用与 token，属于典型的"结果偏差"。

五、根因与边界

  • 机制：占位符与真实值的映射是请求级内存映射，只对当前响应生效。一旦占位符被写进客户端持久化的会话历史，后续任何请求都无法再还原它——无论该请求是否经过脱敏。
  • 触发条件：泄漏窗口内（修复前）的 /v1/responses 流式响应没有还原 reasoning 与 content_part 中的占位符，导致占位符被客户端当作正文保存。
  • 影响性质：网关当前的脱敏逻辑正确；问题是历史污染数据的长尾，表现为 Agent 执行失败、推理偏差与持久化文档污染，而不是脱敏功能本身失效。
  • 不在本次范围：清理会话历史与本地文档属于写入/修复动作，本轮为只读诊断，未执行。
